# 旧助手登记与新版默认组合的衔接调查

日期：2026-11-24。状态：合成样例调查完成；未复现读写缺陷；真实现场根因待现场数据佐证。来源：[GitHub #4](https://github.com/HybridRbt/GachaOps-public/issues/4)（历史 HYB-118），衔接[助手全局登记设计](助手全局登记设计.md)。

## 结论（限定范围）

对本文构造的明确合成状态——“默认组合只登记一项、目录外另有旧七登记文件”——可以由**组合选择与目录外旧文件未导入**完整解释，无需假设丢数据：旧版把接入路径存在每个组合内；新版启动闸门只迁移数据目录内的旧组合文件，目录外旧文件按设计不被自动扫描，其余登记经「导入 → 预览 → 确认」进入全局登记。**该样例未复现任何读取或保存缺陷**；没有现场旧数据目录、选中组合与旧文件来源的证据，不能把真实 #4 的根因定死于此，也不能据此单方面关闭该 issue。

## 复现方法与前提

```bash
python scripts/repro_registry_link.py --all --out issue4-results.json
```

- 前提：仓库根目录运行；可选 UI 依赖 PySide6（`requirements-desktop.txt`）已安装；脚本自设 `QT_QPA_PLATFORM=offscreen` 并把仓库加入 `sys.path`，无需真实安装目录。
- 每个场景在独立子进程运行（240 秒超时守卫）；R6 的“重开”再由一个真正的独立操作系统进程（不同 PID，子进程内重建 QApplication）读取同一临时数据根。
- 全程零启动：`QProcess.start` 被替换为“记录并立即抛错”，任何启动尝试都会使场景失败；结果中逐阶段保留 `launches` 列表。
- 每个场景直接断言核心不变量（登记数量与逐字段路径、逐行勾选/顺序/game_start/timeout 与输入比对、取消前后全量文件清单逐字节一致、外部源文件字节不变、导入只允许“一个新组合目录 + 一个事务备份回执 + 登记文件”的精确增量），任一断言失败即退出非零。`REPRO_NEGATIVE=1` 运行 R1 会以故意错误的期望登记数运行，用于证明校验确实会失败（实测输出 `registry count 7 != 6`，退出码 1）。
- 输出脱敏：写入前对所有字符串递归替换临时目录与样例安装前缀为 `<tmp>`/`<sample>`，并做泄漏断言（大小写不敏感）；stderr 在汇总前也按系统临时目录前缀脱敏。真实路径只可能出现在本地私有日志中。
- 本文档对应的脚本版本：分支 `investigation/issue-4-registry-link`，提交 `9cbee25`（初版，保留作 RED 对照）之后的返修提交。

## 判定与边界

- 本样例范围内：组合选择行为正常；#4 观察态可由“目录外旧文件未导入”解释；未复现读写缺陷。
- 缺口（产品决定，非缺陷）：迁移确认框不提示“目录外旧文件仍含登记，可导入恢复”；是否补充指引由维护者决定。
- 遗留实机项：真实安装目录下的接入检查（版本/原生设置 → “已接入，需处理”）属于运行资格链路，不影响登记衔接结论，不在合成范围内；真实 #4 现场如需定案，需现场数据目录的只读快照（登记数、组合清单、目录外旧文件）。
