# 旧助手登记与新版默认组合的衔接调查

日期：2026-11-24。状态：合成样例调查完成；未复现读写缺陷；真实现场根因待现场数据佐证。来源：[GitHub #4](https://github.com/HybridRbt/GachaOps-public/issues/4)（历史 HYB-118），衔接[助手全局登记设计](助手全局登记设计.md)。

## 结论（限定范围）

对本文构造的明确合成状态——“默认组合只登记一项、目录外另有旧七登记文件”——可以由**组合选择与目录外旧文件未导入**完整解释，无需假设丢数据：旧版把接入路径存在每个组合内；新版启动闸门只迁移数据目录内的旧组合文件，目录外旧文件按设计不被自动扫描，其余登记经「导入 → 预览 → 确认」进入全局登记。**该样例未复现任何读取或保存缺陷**；没有现场旧数据目录、选中组合与旧文件来源的证据，不能把真实 #4 的根因定死于此，也不能据此单方面关闭该 issue。

## 三个可判定不变量

脚本与报告按以下三条可判定不变量组织；任一不成立即退出非零。

- **(A) 公开输出无路径泄漏**：任何正常或失败输出（含 `--all` 聚合、FAIL 结果与 stderr）只经唯一脱敏出口发布；替换与泄漏断言均大小写不敏感，覆盖原始、正斜杠、双反斜杠（repr 转义）形式；子进程任何异常（含非断言崩溃）都转为同一条脱敏失败记录，不输出裸回溯；脱敏、泄漏检查或序列化自身异常时只发布固定安全文案与最小安全结果，不引用原始错误文本。父进程显式按 UTF-8 解码子进程输出（`errors='replace'`），不受系统 ANSI 代码页影响。
- **(B) PASS 仅当真实对象逐项匹配输入**：组合的运行字段由源文件原始行经统一投影 helper 逐行比对（id/顺序/勾选/game_start/timeout）；每个声称“合成成功”的位置必须真实调用 compose 成功且采用登记表路径，且合成结果逐行核对 id/顺序/enabled/game_start/timeout 与 repeat_limit（执行器实际收到什么就核对什么）；合成被拒只允许出现在明确预期 blocked 的场景。
- **(C) 导入只允许声明增量**：文件库存由同一 helper 前后比较，拒绝任何文件消失；未变化文件逐字节一致；导入增量恰为“一个新组合目录（config.json + name.json，全新 UUID，不复用现有 id）+ 一个事务备份回执（manifest.json + complete.json）+ 登记文件变化”，无悬挂迁移 journal。

## 复现方法与前提

```bash
python scripts/repro_registry_link.py --all --out issue4-results.json
```

- 前提：仓库根目录运行；可选 UI 依赖 PySide6（`requirements-desktop.txt`）已安装；脚本自设 `QT_QPA_PLATFORM=offscreen` 并把仓库加入 `sys.path`，无需真实安装目录。
- 每个场景在独立子进程运行（240 秒超时守卫）；R6 的“重开”再由一个真正的独立操作系统进程（不同 PID，子进程内重建 QApplication）读取同一临时数据根。
- 全程零启动：`QProcess.start` 被替换为“记录并立即抛错”，任何启动尝试都会使场景失败；结果中逐阶段保留 `launches` 列表。
- 输出脱敏见不变量 (A)：父进程在写出聚合结果前还会按系统临时目录的全部文本变体再扫一遍（含 FAIL 聚合输出）。
- 本文档对应的脚本版本：分支 `investigation/issue-4-registry-link`；`9cbee25`（初版）与 `6819cb0`（上轮返修）保留作历史对照，本稿对应其后的终审返修提交。

## 失败路径覆盖说明

- 本轮合成样例覆盖：迁移取消（R4）、导入取消（R2）、冲突不选择被拒（R5/R2 API 层）、不完整登记延后（R5）、上表 4 组注入故障。
- 事务中断/发布失败/备份损坏等失败恢复路径沿用 PR #8 期间的回归（tests/test_registration_migration.py 的 MigrationContinueTests、ImportContinueTests、JournalArchiveRaceTests、ContinueRegistrationRaceTests 与 tests/test_registry.py），本轮未重复构造；产品代码在本轮未改动，PR #8 期间实测通过的 `tests.test_profiles tests.test_registration_migration tests.test_registration tests.test_registry`（51 项）与 `tests.test_desktop_ui`（37 项）结果仍然适用，本轮仅运行本脚本的正向与负向证据。

## 判定与边界

- 本样例范围内：组合选择行为正常；#4 观察态可由“目录外旧文件未导入”解释；未复现读写缺陷。
- 缺口（产品决定，非缺陷）：迁移确认框不提示“目录外旧文件仍含登记，可导入恢复”；是否补充指引由维护者决定。
- 遗留实机项：真实安装目录下的接入检查（版本/原生设置 → “已接入，需处理”）属于运行资格链路，不影响登记衔接结论，不在合成范围内；真实 #4 现场如需定案，需现场数据目录的只读快照（登记数、组合清单、目录外旧文件）。
