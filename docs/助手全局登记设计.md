# 助手全局登记设计

日期：2026-11-10。状态：待用户审阅；尚未实现。

## 目标与已确定的边界

来源：[GitHub #5](https://github.com/HybridRbt/GachaOps-public/issues/5) 及本卡用户澄清。

用户已确定：助手接入跨组合生效；组合表示本轮要运行哪些助手。采用独立全局登记。旧组合为同一助手保存不同接入路径时，保留原配置，用户选择后再迁移。

本设计中的“全局”指同一个 `data_root`，沿用 `app_paths.py` 的数据目录解析，不跨 Windows 用户或不同数据目录隐式共享。一次登记供该目录中的全部组合使用；新建、切换、保存、改名或删除组合均不改变登记。

本轮只交付设计。实施时不启动游戏、不修改原生助手预设，不改执行锁、进程所有权、清理、隔离和重试协议。

## 现状与方案选择

- `profiles.py` 将安装路径、选择、顺序和运行设置一起保存在每个组合的 `config.json`。
- `registration.py:commit_registration` 返回修改后的组合；`desktop.py:persist_profile_data` 立即保存当前组合。
- GUI 启动默认选创建时间最早的组合。离线复现表明，B 中登记后重启回到 A 会显示待接入；B 的数据仍在。在 A 再登记后，下次启动正常。这是与 issue 高度吻合的复现路径，现场原因仍缺日志和配置快照。
- GUI 执行前已将完整配置写入 `runs/gui-*/assistants.json`；CLI/worker 读取 `schema_version=1` 的完整配置。
- 提权通过 GUI `--config` 传递临时完整配置，导入也直接保存完整组合；这些入口都要适配。

已选方案是独立登记库加组合引用。仅恢复上次组合不能满足跨组合接入；向所有组合复制路径仍存在多个权威副本，容易在保存、导入或多窗口时回写旧值，因此不采用。保持执行快照接口可减少对执行器的影响。

## 数据结构与字段归属

### 全局登记：`config/assistant-registry.json`

```json
{
  "schema_version": 1,
  "kind": "assistant_registry",
  "revision": 1,
  "assistants": {
    "ok-ww": {"installation_root": "C:/Assistants/ok-ww"},
    "maa-gf2": {
      "installation_root": "C:/Assistants/MaaGF2",
      "entry_executable": "C:/Assistants/MaaGF2/MaaGF2.exe"
    }
  }
}
```

- 键为内置目录 `AdapterSpec.adapter_id`，一类助手在本数据目录有一份有效登记。本次不增加多安装实例或账号管理。
- 值只允许该适配器的 `registration_fields`：`installation_root`、`entry_executable`、`game_path`。未登记则无此键；不以 `enabled` 表示接入状态。
- `installation_root` 为绝对目录；入口为目录内绝对文件路径，游戏路径为绝对文件路径。新登记沿用当前链接检查、适配器检查和字段白名单。
- `revision` 为正整数，每次成功修改递增；拒绝未知 schema、kind、适配器和字段。登记库损坏必须报错，不能退回旧组合、自动清空或改读另一目录。
- 不持久化“永远就绪”的判断。存在登记但目录暂不可用、版本变化或原生设置不足时显示“需处理”，保留登记。只有没有登记才显示“待接入”。

### 组合：`config/profiles/<uuid>/config.json`

```json
{
  "schema_version": 2,
  "kind": "assistant_profile",
  "revision": 1,
  "repeat_limit": 0,
  "assistants": [
    {"id": "wuthering-waves", "adapter": "ok-ww", "enabled": true,
     "game_start": "assistant", "timeout_seconds": 1800}
  ]
}
```

- `id` 沿用现有组合内唯一标识；`adapter` 引用登记库键；数组顺序就是执行顺序。
- 不保存任何接入路径。`enabled`、`game_start`、`timeout_seconds`、`repeat_limit` 保持现有运行语义，归组合所有；这是本设计的实施选择，不改变用户已明确的接入边界。
- `name.json`、组合 UUID 和名称规则保留。创建默认组合时显示内置助手目录并默认不勾选，已有全局登记立即可见。
- 同一 `adapter` 的多个旧行可保留各自 `id` 和运行设置，但只能引用同一登记，不能借行标识覆盖接入路径。
- 可保存引用尚未接入助手的组合。执行选中且未登记的助手时明确阻止启动，不能静默取消勾选；无关的未选助手不阻止运行。
- 校验继续拒绝重复行 `id`、未知适配器、不支持的 `game_start`、非布尔 `enabled`、非正有限超时和非法重复上限。未知字段不静默丢弃。

### 运行快照：`runs/gui-<uuid>/assistants.json`

组合运行字段与当前登记合成现有 `schema_version=1` 完整配置，经 `validate_assistants` 校验后原子保存，再交给 worker。该文件不带组合/登记存储字段 `kind` 或 `revision`。

已经开始的任务、检查或重复链始终使用这一份快照。后续修改登记只影响下次检查/运行，不热更新快照，不重写历史运行文件。

## 存储接口与一致性

建议增加 `RegistrationStore`，组合读取、引用合成和迁移由配置服务协调，GUI 不再直接用 `load_assistants(profile_path)` 读取存储态组合。以下是行为契约，具体 Python 类型命名可在实施计划中调整。

| 接口 | 输入与输出 | 写入边界 |
| --- | --- | --- |
| `RegistrationStore.read()` | 校验后的登记及 revision | 只读；缺失旧库返回迁移要求，不创建空库覆盖事实 |
| `inspect_registration(adapter, fields, game_start=...)` | 候选登记、blockers、warnings、observations | 只读检查；运行模式只参与本次校验，不写入登记 |
| `RegistrationStore.commit(adapter, inspection, expected_revision)` | 新登记 revision | 仅更新全局登记并备份原值，不写任何组合 |
| `ProfileStore.load_profile(id)` | schema 2 组合及 revision | 返回存储态组合，不混入路径 |
| `ProfileStore.save_profile(id, profile, expected_revision)` | 新组合 revision | 仅写组合；含接入字段直接拒绝，避免陈旧 UI 回写路径 |
| `compose_configuration(profile, registry)` | schema 1 完整运行配置 | 深复制；不改变两个输入；选中未登记时返回明确错误 |
| `preview_registration_migration()` | 源摘要、候选登记、冲突、目标预览 | 只读；不能遍历历史 runs 或备份作为接入权威 |
| `commit_registration_migration(preview, choices)` | 已完成事务或可恢复失败 | 摘要和选择全部有效后才提交 |

所有配置写入和组成运行快照时，使用按规范化 `data_root` 标识的跨进程短时配置锁；可复用 `ExecutionLock` 的互斥实现，但使用不同 mutex 名称。配置锁不替代或重置现有全局执行锁。配置写入以 `revision` 和源字节摘要检测旧窗口，冲突时要求刷新，不能“最后写入者胜出”。

普通登记修改先在同目录备份旧文件，再用现有 `save()` 的 flush/fsync/原子替换发布新文件。备份失败、权限失败、无效数据、锁占用均保留旧文件并提示失败。父目录与文件均检查链接和越界；无效登记库不能自动重建。

组合快照在持有配置锁时同时读取组合和登记并完成拷贝，之后释放配置锁再进入现有执行流程。不要持配置锁等待游戏结束。GUI 切组合、窗口重新激活、手动检查和开始运行时读取最新登记 revision；变化后清除旧检查结果并刷新行状态。全局登记更新不能修改其他组合的选择和运行设置。

## GUI、导入及提权

- 任何组合中的“去接入/设置接入”编辑同一份全局登记，提示“此接入设置对所有组合生效”。普通登记和 BetterGI 快捷登记必须走同一提交服务。
- 路径登记可在存在原生准备阻碍时保存，界面显示“已接入，需处理”。不得像旧 `commit_registration` 那样顺带把组合行设为禁用；能否运行由本轮检查决定。
- “保存组合”仅保存运行字段；“删除组合”只备份/删除组合，不删除登记。登记成功后不创建额外“我的组合”，也不依赖点击“保存组合”。
- 外部 schema 2 组合导入只添加引用，不改变登记。外部 schema 1 完整配置先拆分为组合和登记候选；导入预览显示新增登记与冲突。与现有登记冲突时，使用同一个选择流程；取消时组合与登记均不变，不隐式覆盖当前全局路径。
- schema 1 导入涉及登记和新组合的跨文件写入，必须复用下述 `prepared/complete` 事务。事务种类为 `import`，清单记录原登记、新组合 UUID、`name.json` 和 `config.json`、源文件摘要及目标摘要；导入来源只读、不加入可覆盖目标。恢复使用清单内固定 UUID，不重复创建组合。导入是否保持原全局值或替换为所选候选必须在确认预览中明确显示，不能发布登记后忽略组合创建失败。
- GUI `--config` 保留“临时组合草稿”的用途，安装路径只能作为显式导入候选，不能覆盖有效登记或成为优先读取来源。冲突未解决时不启用该草稿的运行操作；选择后草稿同样使用全局登记。
- 提权改用 GUI `--handoff <path>`，在 `runs/gui-setup-<uuid>/handoff.json` 保存 `schema_version=1`、`kind=desktop_handoff`、`source_profile_id`（UUID 或 null）、`source_profile_revision`（正整数或 null）、`registry_revision`（正整数）及 `draft`（只含运行字段的 schema 2 组合）。同时保留原 `--data-root`；handoff 不保存接入路径，不传给 worker。加载时校验 kind、字段、路径边界和链接；无效 handoff 明确报错。
- 新管理员窗口读取同一登记库。原窗口有未保存运行选择时传草稿，不强制保存，也不创建新组合；保存时仍更新来源 UUID，若原组合 revision 已变或来源已删除则提示冲突，不能自动另存或覆盖。登记 revision 改变时保留草稿运行设置、采用最新全局登记并清除检查结果。旧版提权传来的 schema 1 临时配置按 GUI `--config` 导入规则处理。
- worker/CLI 的 `check-assistants --config`、`run-assistants --config` 继续接收显式 schema 1 完整快照，不隐式写登记库。独立 CLI 配置仍是调用者指定的执行输入，不是 GUI 的接入来源。schema 2 存储态组合不能直接传给旧执行器，必须先合成；GUI 所有 worker 入口必须合成。
- 旧版程序不识别 schema 2；不支持新旧 GUI 同时编辑同一数据目录。迁移预览提示关闭旧窗口、保留旧文件备份；不能声称新锁能约束旧程序。

## 旧数据迁移与冲突处理

### 发现和选择

启动发现旧 schema 1 组合而无有效迁移完成记录时，进入迁移预览，不自动重写真实配置，不创建替代默认组合。用户可取消并退出，原文件保持可用。全新数据目录可直接创建空登记与 schema 2 默认组合。

按 `adapter` 收集所有现存组合中的非空接入。候选身份是完整路径元组 `(installation_root, entry_executable, game_path)`，不能只比较根目录；缺少可选入口与显式入口先视为不同候选，不猜测等价。相同元组去重，空接入不覆盖非空接入。全局登记已存在时也作为候选，不能被旧组合覆盖。

路径仅按宿主平台的绝对路径规则做词法规范化；Windows 使用 `normcase/normpath` 比较，不依赖磁盘在线、不解析链接、不按文件时间猜测最新路径。不把不同盘符、联接或符号链接猜成同一安装。无法唯一证明的情况留给用户。

存在多个候选时，界面按助手列出来源组合名称/UUID、各字段、当前全局值（如有），由用户选择一个完整候选；禁止跨候选拼接字段。用户可取消，或选择“稍后重新接入”，后者不生成该助手登记并保留组合的已选状态，启动时明确提示未登记。所有冲突有选择后，才能点击“确认迁移”。无冲突也要显示摘要后确认。

登记路径已失效不等于冲突，不自动丢弃。可保留其绝对路径并标记需重新检查。非法 schema、相对路径、未知适配器、链接/目录越界或损坏组合阻止迁移，报告具体源文件；不能跳过文件后声称迁移完成。

### 提交、失败与重启恢复

1. 预览记录全部源组合（包含 `name.json`）和已有登记文件的原始字节 SHA-256、路径、文件清单、revision、候选与选择标识。提交时在锁内重新列举并核对，包括新增/删除组合；有变化要求重做预览。每个目标的源状态必须为 `{exists: true, sha256: ...}` 或 `{exists: false}`，不能用空字符串摘要代替原本不存在。
2. 迁移同时取得既有全局执行锁和配置锁（固定顺序：执行锁 → 配置锁）。只在本数据目录 journal 为 `unused` 或 `idle` 且没有未核实清理时执行；非空 idle journal 仍需 `cleanup_verified=true`。不能迁移时保留可读预览，不开始检查或运行。
3. 在 `backups/registration-migrations/<uuid>/` 保存原始字节、文件清单、源摘要、用户选择及完整目标文件，并校验备份和目标摘要。无自动过期删除；本地备份含绝对路径，不纳入公开材料或默认诊断导出。
4. 先原子写 `config/registration-migration.json`，状态为 `prepared`，含事务种类 `migration` 或 `import`，指向备份 UUID、清单摘要和全部源状态/目标摘要。此时再发布登记及 schema 2 组合，分别用同目录临时文件原子替换；最后把事务标记为 `complete`。一个数据目录同一时刻只有一笔待完成事务；下一笔事务开始前，必须将上一笔 complete 回执归档到其备份目录。迁移和导入均沿用第 2 步的锁顺序及执行状态门槛。
5. 配置服务在任何读写/合成入口先检查事务状态。`prepared` 时不暴露混合状态，不运行、不允许普通配置写入；重启后显示“继续迁移”或“继续导入”。用户确认继续后，在同样两把锁下核对每个目标：源原先存在时，只接受匹配源摘要或目标摘要的文件；源原先不存在时，只接受目标仍不存在或已匹配目标摘要。尚未发布则继续写目标，已匹配目标则跳过。发现第三种内容、原本存在的文件丢失、未纳入清单的组合变更或备份损坏则停止并报告，不覆盖外部改动。新建目标父目录允许在继续时补建，但路径检查仍须通过。
6. 完成前核对全体目标，才发布 `complete`。迁移完成后不再从旧组合或备份反向补写登记。清单中的组合 UUID、名称、顺序、选择、运行设置逐项保留。

事务不是文件系统的多文件原子替换；它通过配置服务的准备态阻止半迁移数据被使用，并以字节摘要实现幂等继续。迁移开始前的取消零写入；开始后的故障保留完整备份和事务，不能把部分失败显示成成功。此轮只提供向前恢复；从备份整体回退属于显式维护操作，不自动覆盖已开始使用的新配置。

## 错误与验收

必须区分：未登记、已登记但路径/原生设置需处理、登记库损坏、待迁移/待选择、源已变化、配置正被修改和迁移写入失败。错误不得变成空默认组合，不得静默选用某个旧路径。诊断导出维持当前白名单，不直接添加登记、迁移备份或本机路径。

实施时至少覆盖以下离线回归，所有真实目录均用 fixture，不启动助手或游戏：

- 在 A 登记后切换 B、新建 C、退出重开，三者均识别同一接入；选择和顺序各自保留。
- 修改登记后，旧组合保存、删除组合和旧窗口保存不能回写路径；revision 冲突有提示。
- 所有接入入口（包括 BetterGI）立即保存全局登记；取消预览不写入，不改变任何组合勾选。
- 已登记目录暂不可用显示需处理；恢复目录后重新检查即可，不要求再次登记。
- 无冲突迁移、同根不同入口冲突、空值与非空合并、用户取消/选择、多组合同适配器、源摘要变化和重复迁移。
- 对每个发布步骤注入写入失败，再重启继续；原字节可追溯，半迁移不能合成任务，外部改动不被覆盖。
- 导入 schema 1/schema 2、未知字段/版本、损坏登记、非法路径、链接和不支持的适配器均有明确行为。
- 提权前后保留数据目录、组合身份和未保存选择，安装路径只来自全局登记；旧 schema 1 草稿不会静默覆盖。
- 两个窗口读旧 revision 后并发保存不丢数据；登记变更使检查结果失效；运行中更新登记不改变已生成快照。
- CLI schema 1、worker、现有执行锁/journal、重试和清理测试保持原语义。
